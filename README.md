# kkokkkok-multi-research-poc

여러 사진의 누적 분석 실험입니다. 같은 구역(EXIF 위치 100m 묶음)에서 찍힌 사진들의 단서를 모아, 사진 한 장으로는 드러나지 않던 위치가 여러 장으로 드러나는지를 봅니다.

사진 한 장의 분석(단서 추출, 규칙 판정)은 `KkokKkok-Research-PoC/location-cue-lab`의 기록을 그대로 읽어 씁니다.

## 한눈에 보기

| 단계 | 하는 일 | 쓰는 것 |
|---|---|---|
| 구역 묶기 | 사진의 EXIF 위치를 읽어, 모든 사진 쌍이 100m 안인 묶음을 구역으로 삼음 | `sharp`, `exif-reader`, 완전 연결 군집 |
| 이미 드러난 것 빼기 | 단독 분석이 높음으로 잡은 단서와, 그 글자·물체가 다시 나온 단서를 뺌 | 연구 저장소의 꼭꼭 규칙 판정, 글자 비교, 두 사진 비교(Claude) |
| 중복 제거 | 여러 사진에 나온 같은 증거를 한 번만 셈 | 글자 정규화, 같은 물체 판정(Claude) |
| 조합 판정 | 남은 증거를 함께 읽으면 더 좁혀지는지 판정하고, 조건에 안 맞는 조합은 코드가 걸러 냄 | Claude(글만 보는 호출 1회), 코드 검증 |
| 지도 확인 | 조합이 실제로 몇 곳에 있는지 세어 위험도를 고침 | 카카오 장소 검색(영역 분할, 반경 검색) |
| 뷰어 | 구역, 후보, 위험이 정해진 과정을 지도와 사진으로 보여 줌 | Node 내장 서버, Leaflet, OpenStreetMap 타일 |

위험도는 좁혀지는 범위로 정합니다. 지점 하나면 높음, 몇 곳·동네면 중간, 도시·구나 그보다 넓으면 낮음입니다. 누적으로 "더 위험해졌다"고 하는 것은 조합이 가장 좁은 단독 단서와 가장 드러난 단독 사진보다 더 좁을 때뿐입니다.

## 구역 지도

```bash
npm run zones
```

```bash
npm start
```

`http://localhost:3020`에서 구역(원)과 사진(점)을 지도에서 봅니다. 구역이나 점을 누르면 그 구역의 사진과 단서가 왼쪽에 나옵니다. 회색 점은 100m 안에 다른 사진이 없어 묶음이 없는 사진입니다.

- `scripts/build-zones.mjs`: 구역 자료(`private-data/zones.json`)를 만듭니다. 구역 구성은 연구 저장소의 `gps-clusters-100m.json`(완전 연결, 모든 사진 쌍이 100m 이내)을 따릅니다.
- `server.mjs`: 이 컴퓨터에서만 열리는 뷰어 서버입니다(127.0.0.1).
- `public/`: 지도 페이지입니다. 지도 타일은 OpenStreetMap에서 받습니다.

## 구역 누적 분석

```bash
node scripts/analyze-zone.mjs G3
```

구역의 사진들에서 단독 분석이 이미 잡아낸 높음 단서를 빼고 남은 중간·낮음 단서를 모아, 사진을 함께 읽으면 위치가 더 좁혀지는지 판정합니다. 규칙은 `lib/zone-analysis.mjs` 맨 위에 적혀 있습니다.

1. 사진별 증거 중, 단독 분석이 이미 높음으로 잡은 단서에서 나온 것은 뺍니다. 혼자 높음인 단서와, 사진 한 장 안에서 지점 하나까지 좁혀지는 조합에 쓰인 단서가 여기에 해당합니다. 그렇게 뺀 글자가 다른 단서나 다른 사진에 다시 나오면 그 단서도 빼고, 글자 없는 중간 단서는 이미 뺀 것과 같은 물체인지 두 사진을 비교해서 같으면 뺍니다.
2. 여러 사진에 나온 같은 증거는 한 번만 셉니다. 글자는 같은 글자면, 낮음 단서는 종류가 같으면, 중간 단서는 사진 비교에서 같은 물체로 판정됐을 때 합칩니다.
3. 고유 증거 목록으로 구역 판정 프롬프트(`private-data/zone-analysis/<구역>/prompt.txt`)를 만들어 Claude에 한 번 묻습니다. 연구 저장소의 `.env`에 있는 키(`ANTHROPIC_API_KEY`)와 모델 설정을 그대로 씁니다. 답은 같은 폴더의 `response.txt`에 남아서, 프롬프트가 바뀌지 않으면 다시 실행해도 새로 묻지 않습니다. `--handoff`를 붙이면 호출하지 않고 프롬프트만 쓰고 멈춥니다.
4. 답에서 조건에 맞지 않는 조합을 코드가 걸러 냅니다(한 사진 안에서 다 보이는 조합, 구성 증거보다 좁아지지 않는 조합 등).
5. 가장 좁은 단독 단서, 가장 드러난 단독 사진과 비교해 누적으로 더 위험해졌는지를 적습니다(`result.json`). 지도에서 구역을 누르면 이 결과가 보입니다.

구역의 모든 사진에 연구 저장소의 `rules`, `evidence` 단계가 먼저 되어 있어야 합니다.

## 지도 확인

```bash
node --env-file=C:/KKokKKok/KkokKkok-Research-PoC/location-cue-lab/.env scripts/verify-zone.mjs G1
```

누적 분석의 "몇 곳으로 좁혀진다"는 모델의 추정입니다. 이 단계는 그 조합이 실제로 몇 곳에 있는지를 카카오 장소 검색으로 셉니다(`KAKAO_REST_API_KEY`, 연구 저장소의 `.env`).

1. Claude가 조합의 단서를 검색 조건으로 바꿉니다. 지역 이름이 적힌 단서는 찾을 범위가 되고, 장소 단서는 장소의 종류(학교, 의류 매장 등)가 됩니다(`map-spec.json`).
2. 그 지역 안에서 가장 드문 종류의 장소를 전부 찾고, 하나씩 주변에 나머지 종류가 있는지 봅니다. 서로 200m 안에 다 모여 있으면 후보입니다.
3. 후보가 1곳이면 지점 하나(높음), 2~5곳이면 몇 곳(중간), 더 많으면 도시·구(낮음)로 조합의 범위를 고치고, 구역의 위험도를 다시 계산합니다(`map-check.json`).

지도에서 구역을 누르면 실제 구역(빨강)과 같은 패턴이 있는 다른 곳(보라)이 표시되고, "위험이 정해진 과정 보기"의 4단계에 후보 지도와 목록이 나옵니다.

- 모양이나 분위기(화강석 교문, 오래된 본관)는 지도에서 찾을 수 없어 장소의 종류만 셉니다. 그래서 센 개수는 실제로 맞는 곳의 상한입니다.
- 사진의 좌표는 카카오에 보내지 않습니다. 지역 이름과 그 안의 공개 장소만 묻고, 어느 후보가 실제 구역인지는 이 컴퓨터에서 판정합니다.
- 조합에 지역 이름이 적힌 단서가 없거나, 검색 결과에 실제 구역이 없으면 위험도를 바꾸지 않습니다.

## 주의

- `private-data/`에는 사진의 좌표와 단서가 들어 있어 커밋하지 않습니다. 저장소에는 코드만 올립니다.
- 지도를 열면 보고 있는 지역의 타일을 OpenStreetMap 서버에 요청합니다. 좌표 자체를 보내지는 않지만, 어느 지역을 보는지는 타일 서버가 알 수 있습니다.
