# kkokkkok-multi-research-poc

여러 사진의 누적 분석 실험입니다. 같은 구역(EXIF 위치 100m 묶음)에서 찍힌 사진들의 단서를 모아, 사진 한 장으로는 드러나지 않던 위치가 여러 장으로 드러나는지를 봅니다.

사진 한 장의 분석(단서 추출, 규칙 판정)은 `KkokKkok-Research-PoC/location-cue-lab`의 기록을 그대로 읽어 씁니다.

## 한눈에 보기

| 단계 | 하는 일 | 쓰는 것 |
|---|---|---|
| 구역 묶기 | 사진의 EXIF 위치를 읽어, 모든 사진 쌍이 100m 안인 묶음을 구역으로 삼음 | `sharp`, `exif-reader`, 완전 연결 군집 |
| 이미 드러난 것 빼기 | 단독 분석이 높음으로 잡은 단서와, 그 글자·물체가 다시 나온 단서를 뺌 | 연구 저장소의 꼭꼭 규칙 판정, 글자 비교, 두 사진 비교(Claude) |
| 중복 제거 | 여러 사진에 나온 같은 증거를 한 번만 셈 | 글자 정규화, 같은 물체 판정(Claude) |
| 조합 판정 | 남은 증거를 함께 읽으면 더 좁혀지는지 판정하고, 조건에 안 맞는 조합은 코드가 걸러 냄 | Claude(글만 보는 호출 1회), 코드 검증 |
| 지도 확인 | 조합이 실제로 몇 곳에 있는지 세어 위험도를 고침 | 카카오 장소 검색(영역 분할, 반경 검색) |
| 뷰어 | 구역, 후보, 위험이 정해진 과정을 지도와 사진으로 보여 줌 | Node 내장 서버, Leaflet, OpenStreetMap 타일 |

위험도는 좁혀지는 범위로 정합니다. 지점 하나면 높음, 몇 곳·동네면 중간, 도시·구나 그보다 넓으면 낮음입니다. 누적으로 "더 위험해졌다"고 하는 것은 조합이 가장 좁은 단독 단서와 가장 드러난 단독 사진보다 더 좁을 때뿐입니다.

## 구역 지도

```bash
npm run zones
```

```bash
npm start
```

`http://localhost:3020`에서 구역(원)과 사진(점)을 지도에서 봅니다. 구역이나 점을 누르면 그 구역의 사진과 단서가 왼쪽에 나옵니다. 회색 점은 100m 안에 다른 사진이 없어 묶음이 없는 사진입니다.

- `scripts/build-zones.mjs`: 구역 자료(`private-data/zones.json`)를 만듭니다. 구역 구성은 연구 저장소의 `gps-clusters-100m.json`(완전 연결, 모든 사진 쌍이 100m 이내)을 따릅니다.
- `server.mjs`: 이 컴퓨터에서만 열리는 뷰어 서버입니다(127.0.0.1).
- `public/`: 지도 페이지입니다. 지도 타일은 OpenStreetMap에서 받습니다.

## 구역 누적 분석

```bash
node scripts/analyze-zone.mjs G3
```

구역의 사진들에서 단독 분석이 이미 잡아낸 높음 단서를 빼고 남은 중간·낮음 단서를 모아, 사진을 함께 읽으면 위치가 더 좁혀지는지 판정합니다. 규칙은 `lib/zone-analysis.mjs` 맨 위에 적혀 있습니다.

1. 사진별 증거 중, 단독 분석이 이미 높음으로 잡은 단서에서 나온 것은 뺍니다. 혼자 높음인 단서와, 사진 한 장 안에서 지점 하나까지 좁혀지는 조합에 쓰인 단서가 여기에 해당합니다. 그렇게 뺀 글자가 다른 단서나 다른 사진에 다시 나오면 그 단서도 빼고, 글자 없는 중간 단서는 이미 뺀 것과 같은 물체인지 두 사진을 비교해서 같으면 뺍니다.
2. 여러 사진에 나온 같은 증거는 한 번만 셉니다. 글자는 같은 글자면, 낮음 단서는 종류가 같으면, 중간 단서는 사진 비교에서 같은 물체로 판정됐을 때 합칩니다.
3. 고유 증거 목록으로 구역 판정 프롬프트(`private-data/zone-analysis/<구역>/prompt.txt`)를 만들어 Claude에 한 번 묻습니다. 연구 저장소의 `.env`에 있는 키(`ANTHROPIC_API_KEY`)와 모델 설정을 그대로 씁니다. 답은 같은 폴더의 `response.txt`에 남아서, 프롬프트가 바뀌지 않으면 다시 실행해도 새로 묻지 않습니다. `--handoff`를 붙이면 호출하지 않고 프롬프트만 쓰고 멈춥니다.
4. 답에서 조건에 맞지 않는 조합을 코드가 걸러 냅니다(한 사진 안에서 다 보이는 조합, 구성 증거보다 좁아지지 않는 조합 등).
5. 가장 좁은 단독 단서, 가장 드러난 단독 사진과 비교해 누적으로 더 위험해졌는지를 적습니다(`result.json`). 지도에서 구역을 누르면 이 결과가 보입니다.

구역의 모든 사진에 연구 저장소의 `rules`, `evidence` 단계가 먼저 되어 있어야 합니다.

## 지도 확인

```bash
node --env-file=C:/KKokKKok/KkokKkok-Research-PoC/location-cue-lab/.env scripts/verify-zone.mjs G1
```

누적 분석의 "몇 곳으로 좁혀진다"는 모델의 추정입니다. 이 단계는 그 조합이 실제로 몇 곳에 있는지를 카카오 장소 검색으로 셉니다(`KAKAO_REST_API_KEY`, 연구 저장소의 `.env`).

1. Claude가 구역에 남은 단서를 전부 검색 조건으로 바꿉니다. 지역 이름이 적힌 단서는 찾을 범위가 되고, 장소 단서는 장소의 종류(학교, 의류 매장 등)가 됩니다. 단서에 체인 이름(GS25 등)이 읽혀 있으면 그 이름으로 좁힙니다(`map-spec.json`).
2. 두 가지 패턴을 셉니다. 구역의 장소 단서를 전부 겹친 것과, 누적 분석이 낸 조합 각각입니다.
3. 종류마다 개수를 먼저 묻고, 가장 드문 종류의 장소를 전부 찾습니다. 나머지 종류는 드문 것부터 하나씩, 아직 남은 곳 주변 200m에서 찾아 겹칩니다. 겹칠 때마다 남는 곳의 수를 기록합니다.
4. 남은 곳이 1곳이면 지점 하나(높음), 2~5곳이면 몇 곳(중간), 더 많으면 도시·구(낮음)로 범위를 고치고, 구역의 위험도를 다시 계산합니다(`map-check.json`).

- 지역 이름이 적힌 단서가 없으면 서울 전체에서 찾습니다. 이것은 사진이 알려 준 것이 아니라 가정이므로, 이때는 6곳 이상이 남아도 범위를 좁힌 것으로 치지 않습니다.
- 실제 구역 근처에서 지도에 나오지 않는 조건(지도에 없는 가게, 잘못 잡힌 조건)은 빼고 셉니다. 이 판단에는 실제 위치를 쓰며, 이 컴퓨터 안에서만 합니다.

지도에서 구역을 누르면 실제 구역(빨강)과 같은 패턴이 있는 다른 곳(보라)이 표시되고, "위험이 정해진 과정 보기"의 4단계에 후보 지도와 목록이 나옵니다.

- 모양이나 분위기(화강석 교문, 오래된 본관)는 지도에서 찾을 수 없어 장소의 종류만 셉니다. 그래서 센 개수는 실제로 맞는 곳의 상한입니다.
- 사진의 좌표는 카카오에 보내지 않습니다. 지역 이름과 그 안의 공개 장소만 묻고, 어느 후보가 실제 구역인지는 이 컴퓨터에서 판정합니다.
- 조합에 지역 이름이 적힌 단서가 없거나, 검색 결과에 실제 구역이 없으면 위험도를 바꾸지 않습니다.

## 누적 노출 위험 점수

"꼭꼭 누적 노출 위험 점수 산출 규칙"(조합 규칙 반영 전)을 그대로 계산합니다. 한 사람의 사진을 구역(그룹)으로 나눈 뒤, 그룹마다 세 가지를 잽니다.

- 위치 특정도 L: 그룹 안 사진의 단서 중 가장 좁은 단위. 사진 한 장 안에서 인정된 조합도 포함합니다.
- 방문일 k: 단서가 있는 사진을 찍은 서로 다른 날의 수
- 거리 가중치 w: 등록 장소와의 거리

이를 반복 점수 A, 생활권 조합 점수 B, 최종 점수 S로 묶습니다. 계산식과 초기값은 `lib/exposure-score.mjs` 맨 위에 있고, 문서의 예시(6·8번)는 `npm test`로 확인합니다.

```bash
npm run zones    # 사진마다 촬영일(날짜만)도 저장
npm run places   # 등록 장소를 폴더 사진으로 임시 추정 → private-data/places.json
npm run score    # 사람(폴더)별 점수 → private-data/exposure/<폴더>.json
```

- 지금은 폴더 하나를 한 사람으로 봅니다(`집_합정`, `학교`, `회사_충무로` …). 등록 장소는 그 폴더 사진들 중 다른 사진들과의 거리 합이 가장 작은 사진의 위치로 임시 추정합니다. 나중에 데이터베이스의 등록 장소로 바꿀 때는 `lib/places.mjs`의 `loadPlaces`만 바꾸면 됩니다.
- 단서의 단위는 규칙표 판정(`ruleOf`)을 씁니다. 실제 위치를 알고 한 주소 추정(평가용)은 넣지 않습니다.
- 결과에는 근거 문장(5번)과 보호 편집 제안(8번, 점수가 가장 많이 내려가는 순서)이 함께 들어갑니다.

### 구역 누적 분석과 합친 방식

두 분석은 층이 다릅니다. 구역 누적 분석은 "한 장소의 사진들을 합치면 그 장소가 더 드러나는가"(장소 층)를, 점수는 "여러 장소와 여러 날을 합치면 생활권이 드러나는가"(사람 층)를 봅니다.

- **장소 층(`placeOf`)**: 그룹의 L을 구합니다. 기본은 문서대로 한 사진 안의 단서와 조합만 씁니다. `{cross: true}`를 주면 구역 누적 분석이 찾은 사진 간 조합도 넣습니다.
  - 사진 간 조합은 `zone-analysis/<구역>/result.json`에서 가져옵니다. 지도로 센 조합은 `map-check.json`의 단위를 씁니다.
- **점수 S**: 문서 그대로 사진 간 조합 없이 계산합니다. 사진 간 조합을 넣은 값은 `withCross`에 따로 적습니다.
- **보호 편집**: 사진 간 조합을 넣고 고릅니다. 편집 뒤에도 사진들을 합치면 다시 좁혀지면 경고(`warning`)를 답니다. 사진마다 보이는 단서만 지워서는 부족한 경우는 `crossNeeded`로 알려 줍니다.
  - 여러 후보를 한 번에 지울 때는 후보마다 구성 단서 하나씩만, 가장 적게 지웁니다. 사람이 실제로 하는 편집에 가깝고, 남은 단서가 사진 간 조합을 만들 여지도 그대로 둡니다.
- **`residual`**: 문서 방식(사진 한 장씩)으로 편집 계획을 끝까지 적용한 뒤, 사진 간 조합으로 다시 드러나는 그룹을 적습니다. 구역 누적 분석이 점수에 보태는 몫이 여기서 보입니다.

- **'other' 조합 상한(`capOther`)**: 규칙표 유형(A1~D2) 밖의 조합은 모델이 단위를 정한 것입니다. 대부분 "이름으로 몇 곳까지 좁힌 뒤 외관으로 하나를 고른다"는 판정인데, 이 마지막 단계를 아무도 확인하지 않았습니다.
  - 그래서 검증 전까지는 가장 좁은 구성 단서보다 한 단계까지만 좁히고, 지점 하나로는 세지 않습니다.
  - 지도로 센 사진 간 조합은 검증된 것으로 봅니다.
  - 한 사진 안의 조합과 사진 간 조합 모두에 적용합니다.
- **`noHigh`**: 혼자서 지점 하나인 단서(상호, 학교 이름, 역 이름, 추론 요약 단서)를 모두 뺀 상태의 점수입니다. 구역 누적 분석이 시작하는 상태와 같습니다. 한 사진 안에서 중간·낮음 단서끼리 만든 조합과 사진 간 조합은 남깁니다.

### 뷰어에서 보기

`npm start` 뒤 `http://localhost:3020/exposure.html`(구역 지도 위의 "누적 노출 점수 →" 링크)를 엽니다.

- 맨 위에서 계산 흐름도를 펼쳐 볼 수 있습니다.
- 사람(폴더)을 고르면 다음이 나옵니다.
  - 점수 카드: S, A, B, 한 장씩 편집한 뒤의 점수, 사진을 합쳐 봤을 때의 점수
  - 다시 드러나는 그룹
  - 근거 문장
  - 그룹 표: 줄을 누르면 사진과 결정 단서가 나옵니다
  - 보호 편집 단계별 점수 그래프와 경고
  - 가상 공격자: 상태별 판정과 뒤져야 하는 범위, 가리면 범위가 가장 넓어지는 그룹
- 지도에는 등록 장소(보라 점)와 500m·1km·3km 거리 구간, 그리고 L에 따라 색을 칠한 그룹이 나옵니다. 주황 테두리는 사진을 합치면 다시 드러나는 그룹입니다. 초록 점선 원은 가상 공격자의 후보입니다.

### 가상 공격자

점수는 등록 장소를 이미 안다고 보고 그 주변이 얼마나 드러났는지를 잽니다. 가상 공격자(`lib/attacker.mjs`)는 방향을 뒤집습니다. 등록 장소를 모르는 채 사진에 드러난 장소만으로 생활 거점을 찾아보고, 그 탐색이 등록 장소에 얼마나 빨리 닿는지를 잽니다. 등록 장소는 채점에만 씁니다.

- **공격자가 아는 것**: 그룹마다 단위(L)와 방문일뿐입니다. 위치는 단위만큼만 압니다.
  - 지점 하나: 그 자리
  - 몇 곳: 500m 안 어딘가
  - 도시·구: 2.5km 안 어딘가
  - 몇 곳·도시 수준 그룹은 실제 위치 대신 고정 격자 칸의 한가운데에 둡니다. 같은 구를 다섯 번 알아도 다섯 지점이 아니라 구 하나입니다.
- **근거**: 점수의 거리 가중치 w를 거꾸로 읽습니다. 드러난 장소는 500m 안의 모든 지점에 1, 1km 안에 0.8, 3km 안에 0.5만큼 "여기에 거점이 있다"는 근거를 줍니다. 그룹의 무게는 L × (1 + R)입니다(여러 날 찍은 곳은 최대 2배).
- **뒤져야 하는 범위**: 공격자가 근거가 높은 곳부터 뒤질 때 등록 장소에 닿기까지의 넓이입니다. 반경으로 바꿔 판정합니다.

  | 반경 | 판정 |
  |---|---|
  | 500m 이하 | 찾아냄 |
  | 1km 이하 | 근처까지 |
  | 3km 이하 | 동네 수준 |
  | 그 밖, 또는 닿지 못함 | 찾지 못함 |

  장소 하나만 드러나면 단위에 따라 500m, 1km, 3km가 나옵니다. 드러난 장소들이 등록 장소를 여러 방향에서 둘러싸면 더 좁아지고, 한쪽에 몰려 있으면 덜 좁아집니다.
- **후보**: 근거가 가장 높은 구역을 3순위까지 냅니다. 어떤 등록 장소와도 3km 넘게 떨어져 있고 근거가 2 이상인 후보는 등록하지 않은 생활 거점으로 표시합니다.
- **영향(`influenceOf`)**: 그룹을 하나씩 빼 보고, 뺐을 때 범위가 가장 넓어지는 그룹을 적습니다.

`npm run score`가 세 상태(원래 사진, 높음 단서 없이, 한 장씩 편집한 뒤)의 결과를 `attacker`에 적고, 뷰어는 표와 지도의 초록 원(후보)으로 보여 줍니다. 공격자는 사진을 함께 읽으므로 사진 간 조합을 넣은 L을 씁니다. 점수 S에는 넣지 않습니다.

알아 둘 점:

- 지금 등록 장소는 같은 폴더 사진으로 추정한 값이라, 공격자의 추정과 저절로 가깝게 나옵니다. 제대로 된 검증은 데이터베이스의 등록 장소가 들어온 뒤에 할 수 있습니다.
- 구 경계 대신 고정 격자를 씁니다(사진 좌표를 외부 서비스에 보내지 않기 위해서입니다). 격자 선 가까이에 사는 사람은 도시 수준 단서만으로도 범위가 좁게 나올 수 있습니다.
- 사진 밖의 정보(학교나 직장을 이미 아는 경우)는 넣지 않았으므로, 실제로 찾을 수 있는 정도의 하한입니다.
- 불확실 반경(500m, 2.5km)과 판정 구간은 시작값입니다.

## 파일 하나로 내보내기

```bash
node scripts/export-html.mjs
```

뷰어 전체를 서버 없이 열리는 HTML 파일 하나로 만듭니다(`private-data/export/kkok-zones.html`). 구역 이름을 붙이면(`node scripts/export-html.mjs G1`) 그 구역만 담습니다. 파일에는 사진과 촬영 위치가 들어 있으므로 누구에게 줄지 주의하세요. 지도 타일은 열 때 인터넷에서 받습니다.

## 주의

- `private-data/`에는 사진의 좌표와 단서가 들어 있어 커밋하지 않습니다. 저장소에는 코드만 올립니다.
- 지도를 열면 보고 있는 지역의 타일을 OpenStreetMap 서버에 요청합니다. 좌표 자체를 보내지는 않지만, 어느 지역을 보는지는 타일 서버가 알 수 있습니다.
